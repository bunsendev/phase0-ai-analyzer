# フェーズ0 実装仕様書

## 1. 目的
### 業務面
現場作業を大きく変えず、デスクに戻った後の転記・整理・確認を効率化する。

### 開発面
開発担当者が、業務確認 → 要件整理 → 仕様 → 実装 → テスト → 利用者確認 → 改善、の流れを経験する。

## 2. 1週間の完成目標
1. 共通フォルダへファイル配置
2. ファイル一覧表示
3. 分析対象選択
4. 分析開始ボタン押下
5. ファイル形式判定
6. Excel/CSV読取、PDF抽出、OCR
7. AI分類・帳票種類推定・項目抽出
8. 結果表示
9. 担当者修正
10. 確定結果と修正履歴保存

## 3. 対象形式
必須: xlsx, csv, pdf, png, jpg, jpeg

## 4. 大分類
- ORDER: 受注・依頼
- INVENTORY: 在庫
- SHIPPING: 出荷・配送
- OTHER: その他
- UNKNOWN: 判定不能

## 5. 運用
利用者向けアップロード先は `data/upload/` の1つ。
ファイル配置だけでは分析しない。
利用者が「分析開始」ボタンを押した場合のみ分析する。

## 8. ステータス
READY / ANALYZING / COMPLETED / REVIEW_REQUIRED / FAILED / UNSUPPORTED / CONFIRMED / EXCLUDED

## 9. ファイル解析
### Excel
シート名、行列数、ヘッダー候補、先頭100行、数式・結合セル有無。

### CSV
UTF-8 → UTF-8 BOM → CP932 → Shift_JIS の順で読取。
行列数、ヘッダー、先頭100行。

### PDF
まずテキスト抽出。文字数が閾値未満ならOCR対象。
初期上限10ページ。

### 画像
PNG/JPEG。
幅、高さ、OCR結果、品質警告。

## 10. AI/OCR
内容抽出:
- OCR
- 手書き候補
- 表構造候補

業務分析:
- 大分類
- 帳票種類
- 提供元
- 対象日
- 項目
- 値
- 警告
- 要約

AI出力はJSON。Pydanticで検証する。

## 11. 要確認
以下のいずれか:
- 大分類信頼度 < 0.80
- 帳票種類信頼度 < 0.70
- 項目要確認あり
- OCR結果なし
- UNKNOWN
- error警告
- AI結果とルール判定が矛盾

## 12. 過去結果再利用

確定した以下を保存し、類似帳票分析に再利用する:

- シート名
- ヘッダー
- 固定文字
- 帳票種類
- 大分類
- 共通項目対応
- 提供元
- 修正前後

初期版は単純特徴一致で上位3件を参考例にする。
