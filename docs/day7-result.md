## 2. JPEG要確認ルール

- 画像、画像PDFなどParserが`requires_ocr=true`としたファイルへ、既定で`OCR_REVIEW_REQUIRED`警告を追加する。
- Mock OCRを使用する現在のJPEG分析は`REVIEW_REQUIRED`になる。
- 表示文言は「画像・手書き帳票のため、OCR結果を確認してください。」とした。
- `OCR_REVIEW_REQUIRED=false`で解除できる。実OCRの精度確認後に運用変更でき、画像形式そのものを永久に要確認とするハードコードではない。
- 実データJPEGでRun 5を作成し、`REVIEW_REQUIRED`、警告、Mock OCR結果、元画像の表示を確認した。

## 3. AI入力制限

- 既定値を`AI_MAX_COLUMNS=100`、`AI_MAX_INPUT_CHARS=100000`とした。
- AIへ渡す段階だけで、値のある列を優先し、元の列順を維持して選択する。
- 列数または文字数の上限を超えた場合は切り詰め、`AI_INPUT_TRUNCATED`警告を分析結果へ保存する。
- snapshot、Parser結果、DBへ保存する抽出全文は切り詰めない。

実データの102行×1221列XLSXでは、Parser previewは1221列を保持したまま、AI入力を100列、61,314文字、30 preview行へ制限した。100,000文字の上限内であり、全1221列をAI入力へ渡していない。

## 14. Streamlit UI仕上げ

### 簡略化した内容

- 画面全体を「① ファイル登録、② 分析開始、③ 結果確認」の3ステップへ統一した。
- 分析対象と結果表示対象の2つの選択欄を、1つの「分析するファイル」へ統一した。
- 一覧をファイル名、形式、状態、最新分析結果、要確認、次に行う操作へ絞った。
- 内部ステータスと分類コードを日本語表示へ変更した。
- 分析済み、要確認、確認済みの各状態で、次に行う内容を案内する文言を追加した。

### 非表示・折りたたみにした内容

- 実行環境、AIプロバイダー、アップロード先をトップ画面から除外した。
- run番号、処理方式、モデル名、confidence、判定理由、警告一覧、Parser metadata、raw AI response、確定者情報を「詳細情報（開発・調査用）」へ移した。
- 横長表の全列表示を「元データの全列を表示」へ折りたたんだ。

### 担当者向けに変更した文言

- `READY`等の内部ステータスを「未分析」「分析中」「分析済み」「要確認」「確認済み」「エラー」へ変更した。
- `ORDER`等の分類コードを「受注・依頼」「在庫」「出荷・配送」「その他」「判定不能」へ変更した。
- 「一覧更新」を「ファイル一覧を更新」、「分析対象」を「分析するファイル」、「分析run」を「表示する分析履歴」へ変更した。
- Mock固有の提供元と要約は通常画面で「未判定」と自然文へ置き換え、元の値は詳細情報に保持した。

### ブラウザ確認

- 未分析: 「未分析確認.csv（未分析）」に対して主ボタン「分析開始」と、③の「②の分析開始を押してください」を確認した。
