# 次フェーズ候補

## 目的

フェーズ0で確認できた基盤を維持し、担当者評価とデータ取扱承認を得た後に実運用へ近づける。自動化や外部連携を先行させない。

## A. 早期対応

| 候補 | 目的 | 開始条件 |
|---|---|---|
| 実OCRの比較検証 | 印字・手書き・回転画像の精度を測る | 外部送信可否と正解データ準備 |
| 実AI接続 | 実帳票の分類・項目抽出精度を測る | APIキー運用、送信範囲、コスト上限決定 |
| AI入力列選択 | 横長Excelから業務的に重要な列を選ぶ | 主要列の担当者確認 |
| 担当者UI改善 | 要確認、元資料比較、過去run選択を改善 | 操作確認結果の収集 |
| 実業務CSV・PDF検証 | 形式別の未評価を解消する | Git管理外サンプルと期待値準備 |

## B. 実運用前に必要

| 候補 | 目的 | 完了条件 |
|---|---|---|
| 個人情報・機密情報ルール | 外部送信・保存可能範囲を明文化 | 管理者承認済み方針 |
| APIキー管理 | `.env`を超える安全な配布・更新 | 権限、更新、失効手順の確立 |
| 利用コスト管理 | 1日件数・ページ数から上限を設定 | 予算、警告、停止条件の決定 |
| OneDrive/DB運用 | 同期競合と破損を防ぐ | DB配置、バックアップ、復旧手順の決定 |
| ログ・監査 | 誰が分析・修正・確定したか追跡 | 利用者識別と保存期間の決定 |
| TXT取込方針 | CSVコピーか正式Parserかを決定 | 元システム運用と件数の確認 |
| 一括分析・EXCLUDED判断 | 必要な操作だけ追加 | 担当者による必要性確認 |
| 過去事例再利用 | 類似帳票を参考例として安全に利用 | 類似度評価と誤誘導テスト |

## C. 将来対応

- タブレット入力
- メール自動取得
- ファイル配置後の自動分析
- 外部業務システム連携
- モデル再学習・fine-tuning
- 高度な分析ダッシュボード
- 大量並列処理、高可用性、本番監視
- 本番認証・詳細権限管理

## 推奨順序

1. 担当者操作確認と正解データ確定
2. 情報管理・外部送信・コスト・APIキー方針決定
3. OneDrive/DB運用確立
4. 実OCRと実AIを少数データで比較検証
5. 精度と負担を再評価し、必要なUI・列選択・過去事例再利用を実装

## 次フェーズ開始判定

担当者確認、情報管理承認、コスト上限の3点が揃うまでは、実データを外部AI/OCRへ送信しない。
